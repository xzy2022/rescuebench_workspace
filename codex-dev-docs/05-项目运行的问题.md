# 项目运行问题记录

ID：RUN-001：AutoDL 中 Unreal 拒绝以 root 用户启动
- 问题：Unreal 环境包下载、SHA-256 校验和解压均通过，但运行单点随机测试时 UnrealCV 无法连接 `127.0.0.1:9000`。直接执行 Unreal 二进制后显示 `Refusing to run with the root privileges.`。
- 分析：AutoDL 默认通过 root 用户操作，而 UE5 Linux 二进制内置了拒绝 root 运行的安全限制。项目原启动器将 Unreal 的标准输出和标准错误重定向到 `/dev/null`，因此最初只表现为 UnrealCV 端口连接被拒绝，掩盖了真实原因。
- 解决：创建锁定且禁止交互登录的专用用户 `rescue-runner`，加入 `video` 组；使用 ACL 只授予该用户穿过 `/root` 的权限，并授予 `/root/autodl-tmp/rescue-nomad/runs` 写入权限。新增 `/root/autodl-tmp/rescue-nomad/bin/rescue-run` 启动器，由 root 调用后通过 `runuser` 自动切换到 `rescue-runner`，再执行 Python 和 Unreal。
- 可能风险：不能再直接以 root 运行 RescueBench Python，否则 Unreal 仍会拒绝启动。重置 AutoDL 系统盘后，`rescue-runner`、`acl` 软件包、用户组和 `/root` ACL 都需要重新配置；数据盘中的 Unreal 环境、启动器和实验输出仍会保留。


ID：RUN-002：AutoDL 无桌面容器中的 Vulkan ICD
- 问题：切换到 `rescue-runner` 后，Unreal 已越过 root 检查，但仍在启动阶段退出；直接保留 Unreal 日志后发现 `vpCreateInstance` 返回 `VK_ERROR_INCOMPATIBLE_DRIVER`。
- 分析：服务器原有 `/etc/vulkan/icd.d/nvidia_icd.json` 指向 `libGLX_nvidia.so.0`，该库用于有桌面环境的 GLX 路径。AutoDL 容器采用无桌面运行模式，headless Vulkan 必须改用 `libEGL_nvidia.so.0`。CUDA、PyTorch 和 `nvidia-smi` 正常只能证明计算能力可用，不能证明 Vulkan 图形接口可用。
- 解决：安装 `vulkan-tools`，新增 `/etc/vulkan/icd.d/rescue_nvidia_headless.json`，将 ICD 库设为 `/lib/x86_64-linux-gnu/libEGL_nvidia.so.0`；`rescue-run` 自动设置 `VK_ICD_FILENAMES`、`HOME`、XDG 目录、`UnrealEnv` 和 `PYTHONPATH`。`vulkaninfo` 已识别 Tesla T4，单点随机测试成功连接 UnrealCV、获取观测并执行 829 步，最终在 180 秒因随机策略未完成第二阶段而返回 `TIMEOUT_PHASE2`；测试进程退出码为 0，说明运行环境正常。
- 可能风险：必须通过 `rescue-run` 启动，或手动设置相同的 `VK_ICD_FILENAMES`；缺少该变量时系统仍可能选中错误的 GLX ICD。随机 Agent 的任务超时属于基线策略结果，不应误判为 Unreal、Vulkan 或权限故障。重置系统盘后需要重建 headless ICD 文件并重新安装 `vulkan-tools`。


ID：RUN-003：推荐的服务器启动方式
- 问题：直接执行 Conda 环境中的 Python 不会自动切换用户，也不会设置 headless Vulkan 所需环境变量。
- 分析：非 root 用户、Vulkan ICD、用户 HOME、临时目录、Unreal 路径和 Python 模块路径必须保持一致；手动重复设置容易遗漏。
- 解决：统一使用 `"$PROJECT_ROOT/bin/rescue-run" "$ENV_PATH/bin/python" ...`。例如 Level 0 随机基线命令为：`"$PROJECT_ROOT/bin/rescue-run" "$ENV_PATH/bin/python" benchmark/experiment.py --model random --levels 0 --episodes 1 --no-collision --output "$PROJECT_ROOT/runs/random-baseline"`。可先执行 `"$PROJECT_ROOT/bin/rescue-run" id`，确认输出用户为 `rescue-runner`。
- 可能风险：`rescue-run` 当前固定使用 `/root/autodl-tmp/rescue-nomad` 作为项目根目录；若迁移项目或更改数据盘路径，需要同步修改启动器中的 `PROJECT_ROOT`、用户 HOME 和 Vulkan ICD 路径。
